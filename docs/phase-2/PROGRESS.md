### P2-01 — Fetch aman (anti-SSRF)
- Commit: lihat PR `feat/P2-01-safe-fetch`
- File baru: `apps/api/src/modules/fetch/{address-policy,safe-fetch}.ts`, `apps/api/tests/unit/safe-fetch.test.ts`
- Perilaku: `safeFetch(url, options)` adalah **satu-satunya** jalan worker ke internet.
  - Hanya `https:` di port 443 dan `http:` di port 80. URL berisi kredensial ditolak.
  - Semua alamat hasil DNS harus publik. Yang ditolak:
    - IPv4: loopback, privat (termasuk jaringan Docker `172.16/12`), link-local (termasuk metadata cloud `169.254.169.254`), CGNAT, multicast, reserved, dokumentasi;
    - IPv6: `::1`, `::`, IPv4-mapped/compatible, NAT64, 6to4, Teredo, ULA, link-local, multicast.
  - Bila **satu saja** alamat dalam jawaban DNS privat, seluruh fetch ditolak.
  - Koneksi memakai alamat yang sudah dicek (fungsi `lookup` di-pin), jadi DNS rebinding tidak bisa menukar alamat di antara cek dan koneksi.
  - IP literal dalam bentuk desimal, hex, atau oktal (`2130706433`, `0x7f.1`, `0177.0.0.1`) dinormalkan oleh parser URL, lalu dicek dengan aturan yang sama.
  - Redirect diikuti manual, maksimal 3. Setiap hop dicek ulang: skema, port, kredensial, dan alamat.
  - Satu batas waktu untuk seluruh fetch (default 15 detik), batas ukuran body **setelah dekompresi** (default 2 MiB, menahan bom gzip), dan allowlist content-type.
  - Header `Host`/`Connection` dari pemanggil diabaikan. User-Agent jujur: `NALARA-Ingest/1.0`.
  - Setiap penolakan berupa `FetchBlocked` dengan alasan tetap, tanpa memuat URL atau isi.
- **Ditemukan saat tes:** `BlockList` Node juga mencocokkan alamat IPv4 dengan aturan IPv6 (sebagai `::ffff:a.b.c.d`), sehingga aturan IPv4-mapped sempat menolak **semua** IPv4. Diperbaiki dengan memakai daftar terpisah untuk IPv4 dan IPv6; tes alamat publik kini ikut menjaga ini.
- Test:
  - `pnpm run check` → PASS **405/405**.
  - Termasuk 34 tes fetch aman, memakai server HTTP lokal dan DNS palsu:
    - 22 alamat terlarang ditolak, 5 alamat publik diizinkan;
    - loopback, `localhost`, `[::1]`, `0.0.0.0`, metadata, privat, dan IP desimal/hex/oktal ditolak **tanpa koneksi sama sekali**;
    - jawaban DNS campuran ditolak (rebinding), juga DNS gagal;
    - redirect ke metadata, ke nama yang menunjuk IP privat, dan ke `file:` ditolak; batas 3 hop;
    - skema, port, dan kredensial;
    - respons terlalu besar, bom gzip, dan server lambat (timeout);
    - content-type, `If-None-Match` → 304, dan `Host` yang tidak bisa diganti.
- Security review: PASS. Belum ada pemanggil; modul ini dipakai worker mulai P2-02/P2-04.

### P2-03a — Parser feed (RSS 2.0, RSS 1.0, Atom)
- Commit: lihat PR `feat/P2-03a-feed-parser`. P2-03 dipecah supaya parser bisa ditinjau tersendiri.
- File baru: `apps/api/src/modules/feeds/{xml,feed}.ts`, `apps/api/tests/unit/feed.test.ts`
- **Keputusan: parser XML ditulis sendiri**, tanpa dependensi baru. Alasannya:
  - `fast-xml-parser` 5.x kini membawa 6 dependensi transitif, dan parser XML umum punya riwayat CVE (XXE, prototype pollution, ReDoS);
  - feed hanya butuh sebagian kecil XML, dan penolakan ketat lebih aman daripada toleransi.
- Perilaku:
  - **XML ketat.** Yang dibaca: elemen, atribut, teks, CDATA, komentar, deklarasi XML, 5 entity bawaan + beberapa entity HTML umum (`&nbsp;`, `&mdash;` …), dan referensi angka.
  - **Selalu ditolak:**
    - `DOCTYPE` apa pun, sehingga tidak ada entity eksternal (XXE) dan tidak ada bom entity;
    - entity tak dikenal, `&#0;`, surrogate;
    - tag tidak seimbang, atribut ganda, atribut tanpa kutip, teks di luar root.
  - Batas ukuran (4 juta karakter), kedalaman (32), dan jumlah node (50 ribu). Nama atribut disimpan di objek tanpa prototype, jadi aman dari prototype pollution.
  - **Feed:**
    - RSS 2.0, RSS 1.0/RDF, dan Atom (link `alternate`) menjadi item berisi judul, URL, id penerbit, waktu terbit, dan ringkasan;
    - ringkasan dan judul diubah ke **teks polos** (script/style/komentar/tag dibuang, entity didekode, karakter kontrol dibuang, dipotong 300/500 karakter);
    - maksimal 200 item;
    - encoding UTF-8 (BOM dilewati) atau Latin-1/Windows-1252 sesuai deklarasi; selain itu ditolak.
  - **URL kanonik:** hanya `http(s)` absolut tanpa kredensial; link relatif di-resolve terhadap URL feed; fragment dan parameter pelacak (`utm_*`, `fbclid`, `gclid` …) dibuang. Item tanpa link yang layak dilewati.
- **Ditemukan saat tes:** link kosong sempat di-resolve menjadi URL feed itu sendiri (item palsu di inbox). Kini link kosong berarti "tanpa link".
- Test: `pnpm exec vitest run apps/api/tests/unit/feed.test.ts` → PASS **23/23**:
  - 13 bentuk XML berbahaya atau rusak ditolak, termasuk XXE dan billion laughs;
  - batas kedalaman, node, dan ukuran;
  - prototype pollution;
  - URL kanonik dan link berbahaya (`javascript:`, `data:`, kredensial);
  - HTML → teks polos tanpa script;
  - RSS 2.0, Atom, dan RSS 1.0;
  - batas item, bukan-feed, encoding buruk, Latin-1, dan BOM.
- Security review: PASS. Belum ada pemanggil; dipakai worker di P2-03b/P2-04.

    - app hanya boleh mengubah status inbox (`status`, `status_changed_at`) dan tidak bisa mengubah judul atau isi;
    - item dan run tidak bisa dihapus.
  - Penjadwal memakai **jam database** (`now()`), jam yang sama dengan yang menulis `next_fetch_at`.
- **Ditemukan saat tes:**
  1. Versi awal menulis catatan run (immutable) **sebelum** item, sehingga jumlah "item baru" tidak bisa disimpan. Diubah: item dulu, run belakangan, FK `DEFERRABLE`.

    - feed tidak berubah → 304 tanpa item;
    - item lama di balik link pelacak tidak dobel, item baru masuk;
    - catatan run per fetch;
